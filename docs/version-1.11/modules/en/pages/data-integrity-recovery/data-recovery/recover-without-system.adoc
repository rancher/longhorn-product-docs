= Recover from a {longhorn-product-name-tm} Backup without the System Installed
:description: Restore a SUSE Storage backup to a raw or qcow2 image using a YAML template or script by specifying the backup URL, output file format, and other required parameters
:page-languages: [en, de, es, fr, ja, pt, zh]
:revdate: 2026-05-06
:page-revdate: {revdate}
:current-version: {page-component-version}

This command gives users the ability to restore a backup to a `raw` image or a `qcow2` image. If the backup is based on a backing file, users should provide the backing file as a `qcow2` image with `--backing file` parameter.

. Save the following YAML template as a file, for example, `restore.yaml`:
+
[,yaml]
----
apiVersion: v1
kind: Pod
metadata:
  name: restore-to-file
  namespace: longhorn-system
spec:
  nodeName: <NODE_NAME>
  imagePullSecrets:
  - name: application-collection
  containers:
  - name: restore-to-file
    command:
    # set restore-to-file arguments here
    - /bin/sh
    - -c
    - longhorn backup restore-to-file
      '<BACKUP_URL>'
      --output-file '/tmp/restore/<OUTPUT_FILE>'
      --output-format <OUTPUT_FORMAT>
    image: dp.apps.rancher.io/containers/longhorn-engine:<LONGHORN_VERSION>
    imagePullPolicy: IfNotPresent
    securityContext:
      privileged: true
    volumeMounts:
    - name: disk-directory
      mountPath: /tmp/restore  # the argument <output-file> should be in this directory
    env:
    # set Backup Target Credential Secret here.
    - name: AWS_ACCESS_KEY_ID
      valueFrom:
        secretKeyRef:
          name: <S3_SECRET_NAME>
          key: AWS_ACCESS_KEY_ID
    - name: AWS_SECRET_ACCESS_KEY
      valueFrom:
        secretKeyRef:
          name: <S3_SECRET_NAME>
          key: AWS_SECRET_ACCESS_KEY
    - name: AWS_ENDPOINTS
      valueFrom:
        secretKeyRef:
          name: <S3_SECRET_NAME>
          key: AWS_ENDPOINTS
  volumes:
    # the output file can be found on this host path
    - name: disk-directory
      hostPath:
        path: /tmp/restore
  restartPolicy: Never
----
. Make sure that the `application-collection` secret, which allows Kubernetes to pull the engine image from SUSE Application Collection, exists in the `longhorn-system` namespace. For details, see the https://docs.apps.rancher.io/get-started/authentication/#kubernetes[Kubernetes authentication documentation].
. Set the node which the output file should be placed on by replacing `<NODE_NAME>`, for example `node1`.
. Specify the host path of output file by modifying field `hostpath` of volume `disk-directory`. By default the directory is `/tmp/restore/`.
. Set the first argument (backup url) by replacing `<BACKUP_URL>`, for example `s3://<your-bucket-name>@<your-aws-region>/backupstore?backup=<backup-name>&volume=<volume-name>`.
 ** `<backup-name>` and `<volume-name>` can be retrieved from backup.cfg stored in the backup destination folder, for example `backup_backup-72bcbdad913546cf.cfg`. The content will be like below:
+
[,json]
----
{"Name":"backup-72bcbdad913546cf","VolumeName":"volume_1","SnapshotName":"79758033-a670-4724-906f-41921f53c475"}
----
. Set argument `output-file` by replacing `<OUTPUT_FILE>`, for example `volume.raw` or `volume.qcow2`.
. Set argument `output-format` by replacing `<OUTPUT_FORMAT>`. The supported options are `raw` or `qcow2`.
. Set the engine image version by replacing `<LONGHORN_VERSION>`, for example, `{patch-version}`
. Set the S3 Credential Secret by replacing `<S3_SECRET_NAME>`, for example `minio-secret`.
 ** The credential secret can be referenced xref:snapshots-backups/volume-snapshots-backups/configure-backup-target.adoc#_set_up_aws_s3_backupstore[here] and must be created in the `longhorn-system` namespace.
. Execute the yaml using:
+
[,json]
----
kubectl create -f restore.yaml
----
. Watch the result using:
+
[,json]
----
kubectl -n longhorn-system get pod restore-to-file -w
----
After the pod status changed to `Completed`, you should able to find `<OUTPUT_FILE>` at `/tmp/restore` on the `<NODE_NAME>`.

We also provide a script, https://raw.githubusercontent.com/longhorn/longhorn/v{current-version}.x/scripts/restore-backup-to-file.sh[restore-backup-to-file.sh], to restore a backup. The following parameters should be specified:

* `--backup-url`: Specifies the backups S3/NFS URL. For example, `s3://backupbucket@us-east-1/backupstore?backup=backup-bd326da2c4414b02&volume=volumeexamplename"`
* `--output-file`: Set the output file name. For example, `volume.raw`
* `--output-format`: Set the output file format. For example, `raw` or `qcow2`
* `--version`: Specifies the version of {longhorn-product-name} to use. For example, `v{patch-version}`

Optional parameters can be specified:

* `--aws-access-key`: Specifies AWS credentials access key if backups is S3.
* `--aws-secret-access-key`: Specifies AWS credentials access secret key if backups is S3.
* `--backing-file`: backing image. For example, `/tmp/backingfile.qcow2`

The output image files can be found in the `/tmp/restore` folder after the script has finished running.
